## 3. Найдено и исправлено по ходу

1. **Вызов инструментов через llama.cpp** (найдено на Mac): llama.cpp не передаёт начальное поле `input` у вызова инструмента, адаптер падал с `MALFORMED_RESPONSE` на каждом вызове. Теперь отсутствующее поле — пустой объект; проверка аргументов в конце сообщения не ослаблена. Проверено на Mac (llama.cpp) и на Windows (Ollama, E1, M2–M6).
2. **Песочница macOS** (найдено на Mac): профиль Seatbelt ограничивал только запись — команды агента выходили в интернет и читали `.credentials.yaml` через bash. Теперь профиль запрещает исходящие соединения и чтение тех же защищённых путей, что и инструмент чтения (снять — только явно, `DSH_ALLOW_AGENT_NETWORK=1`). Linux и Windows не затронуты.
3. **Новая уязвимость MCP SDK** (бюллетень high вышел после раунда 3): версии `@modelcontextprotocol/client` 2.3.1 и `sdk` 1.32.1; снова 0 high.
4. **Распаковка на Mac:** системный `unzip` не создаёт файлы с не-ASCII именами — в `mac-check.sh` используется `ditto`.
5. **Тесты оригинала** приведены в соответствие с защитами (`7507d5c`, код не меняется): тесты адаптера модели с тестовыми удалёнными адресами явно включают `DSH_ALLOW_REMOTE_MODEL=1`; тест субагента использует разрешённое имя переменной. Итог на сборочной ВМ: 1431 тест прошёл, 39 пропущены намеренно. 10 тестов `sandbox-windows-acl/runner.spec.ts` требуют PowerShell 7 (`pwsh`), которого нет в чистой ВМ («файл не найден» при запуске); сама песочница Windows проверена вживую (A5, A6, E1, E2, M1–M6).
6. Первая версия CSP ломала интерфейс (загрузчику плагинов нужен `eval`) — разрешён `unsafe-eval`; внешние загрузки по-прежнему закрыты.
7. После отказа песочницы агент мог попросить оператора о полном доступе — **механизм закрыт в коде** (`packages/sandbox/sandbox/src/escalation.ts`): повышение только `read-only → workspace-write`.
8. Инструкция: офлайн-установка pnpm 11 без `pnpm_config_trust_policy=off` и `pnpm_config_minimum_release_age=0` бесконечно стучится в registry; `icacls … /T` с флагами наследования оставлял файлы без прав; `install-sshd.ps1` не работал из-за непригодной `TEMP`. Всё исправлено. При переносе обновлений хранилища pnpm заменяется и его индекс (`v11\index.db`), а не только файлы.
9. Windows при загрузке запускала только одну из двух служебных задач — добавлен сторожевой повтор (в `server-setup.ps1` и инструкции).
10. Сборка всех пакетов на ВМ с 3 ГБ памяти не укладывается в стандартную кучу Node — в сборочной ВМ 6 ГБ и `NODE_OPTIONS=--max-old-space-size=4096`.

## 4. Что учитывать при эксплуатации

1. CSP разрешает `unsafe-eval` (нужно интерфейсу); защита от внешних загрузок не ослаблена.
2. Агент читает файлы, доступные `dshsvc` и не помеченные меткой (общие папки). Не хранить там конфиденциальное.
3. Встроенные разрешающие правила Windows для системных служб не трогались (в стенде без шлюза они ничего не дают); на реальном сервере — ревизовать групповой политикой.
4. У релиза OpenSSH 9.5 на GitHub нет опубликованной контрольной суммы; зафиксирован SHA-256 скачанного файла `bd48fe98…096530c`.
5. Поставляется веб-версия; десктоп-приложение не собирается.
6. Подключение облачных моделей по API (GPT, Claude, DeepSeek) в этой сборке заблокировано намеренно (`REMOTE_ENDPOINT_BLOCKED`, облачные провайдеры выключены). Включение означает, что код и файлы, которые читает агент, уходят внешнему провайдеру, — это решение ответственного за безопасность.
